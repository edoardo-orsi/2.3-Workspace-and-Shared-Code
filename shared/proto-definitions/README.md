# proto-definitions

This crate serves as the **central source of truth** for gRPC service definitions within your microservice architecture. It automatically compiles Protocol Buffer files (`.proto`) into Rust code using `tonic` and `prost`, providing a type-safe interface for both clients and servers.

## 🚀 Features

* **Dynamic Discovery**: Automatically crawls the `../../protos` directory for any `.proto` files using `walkdir`.
* **Version Consistency Enforcement**: The build script strictly validates that your directory structure matches your protobuf package versions (e.g., `package auth.v1` must be located in a folder named `v1`).
* **Sync-on-Build**: This crate generates a `generated_protos.rs` file directly in the `src/` directory to ensure the `include_proto!` and `include_file_descriptor_set` are implemented.
* **Reflection Support**: Automatically generates `DESCRIPTOR_SET` constants for each module, enabling easy integration with gRPC reflection and transcoding.

---

## 📂 Required Structure

The build script expects a specific hierarchy to maintain consistency across services. Your protobuf files should be organized as follows:

```text
.
├── protos/                 # Located at ../../protos relative to this crate
│   ├── greeter/
│   │   └── v1/
│   │       └── greeter.proto  # Package must be 'greeter.v1'
│   └── auth/
│       └── v1/
│           └── auth.proto     # Package must be 'auth.v1'
└── proto-definitions/      # This crate
    ├── src/
    │   ├── generated_protos.rs # (Auto-generated by build.rs)
    │   └── lib.rs
    └── build.rs
```

## 🛠 Usage
### Adding a New Proto
1. Place your `.proto` file in the correct versioned folder in the `../../protos` directory.
2. Run `cargo build`.
3. The build script will validate the path, compile the proto, and update `src/generated_protos.rs` automatically.

### Importing in Rust
Once compiled, you can access your services directly from this crate:

```rust
use proto_definitions::greeter_v1::{greeter_client::GreeterClient, HelloRequest};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut client = GreeterClient::connect("[https://my-service.internal:50051]").await?;
    
    // ... use the client
    Ok(())
}
```

### Using Descriptors (Reflection)
Each generated module includes a `DESCRIPTOR_SET` constant:

```rust
// Example using the generated constant for reflection
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let service = tonic_reflection::server::Builder::configure()
        .register_encoded_file_descriptor_set(proto_definitions::greeter_v1::DESCRIPTOR_SET)
        .build()?;
    Ok(())
}
```

### ⚙️ Build Logic Details

The `build.rs` script performs the following automated steps:
1.  **Walks** the `../../protos` directory to find all `.proto` files.
2.  **Parses** each file to extract the `package` declaration.
3.  **Validates** that the folder name matches the version suffix (e.g., folder `v1` for package `*.v1`).
4.  **Compiles** each proto into a unique descriptor set inside `OUT_DIR`.
5.  **Writes** a dynamic `generated_protos.rs` file in `src/` to link all compiled modules.
